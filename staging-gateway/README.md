# Business Snapshot Staging Gateway

Isolated Cloudflare Worker used only for the NON_PRODUCTION Business Snapshot
transport:

browser → Worker gateway → Turnstile Siteverify → isolated Apps Script receiver
→ pinned test library Version 1 → disposable workbook.

The Worker serves a staging-only test form at `/` and accepts submissions only
at `POST /api/business-snapshot`. It is not connected to the production website
or production DNS.

## Security boundaries

- Turnstile is validated server-side for every submission.
- The browser never receives the Apps Script receiver URL or shared secret.
- `acceptedAt` is generated by the Worker.
- The API rejects unknown fields, browser-supplied `acceptedAt`, malformed UUIDs,
  oversized bodies, and invalid normalized fields.
- The Worker uses Cloudflare rate-limit bindings for both a client key and a
  request-ID key.
- Public errors are allowlisted and contain no upstream diagnostics.
- Logs contain only event names, request IDs, safe codes, and HTTP status.

## Local validation

```sh
npm install
npm test
npm run check
npm run deploy:dry-run
```

Copy `.dev.vars.example` to `.dev.vars` for local development and supply only
non-production values. Never commit `.dev.vars`.

## Staging secrets

Configure these through `wrangler secret put --env staging`:

- `BUSINESS_SNAPSHOT_RECEIVER_URL`
- `BUSINESS_SNAPSHOT_RECEIVER_SECRET`
- `TURNSTILE_SECRET_KEY`

The official always-pass Turnstile test sitekey is committed as a public staging
value. Its matching test secret remains a Worker secret even though Cloudflare
publishes it for testing. Test credentials must never be used in production.
